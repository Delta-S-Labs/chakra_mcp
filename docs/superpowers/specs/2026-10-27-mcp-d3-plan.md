# MCP and discovery D3: MCP — implementation plan

Derived from `2026-10-27-mcp-discovery-design.md` (§ numbers refer to it). D3 is PRs 9–11 of §13.
It ships in the release after 0.5.0, with D2. Each PR merges when green.

**Conventions:** as D2's plan. Branches `feat/d3-invoke-by-name`, `feat/d3-directory`,
`feat/d3-agent-endpoints`. New code lives in `relay/src/mcp/`; the existing `/mcp` tools stay in
`handlers/mcp.rs`.

**Settings** (`mcp::McpConfig::from_env`, env-only; added to both `.env.example` files, the
Compose file and the chart notes, with defaults written out):

| Variable | Default | |
|---|---|---|
| `MCP_AGENTS_ENABLED` | `false` (D4 turns it on) | the directory and agent endpoints |
| `MCP_TOOL_WAIT_SECS` | 25 | 0–55; how long an agent-endpoint tool call waits |
| `MCP_MAX_WAITERS` | 200 | concurrent waiting tool calls |
| `MCP_DIRECTORY_PER_IP_PER_MIN` | 60 | |
| `TRUST_FORWARDED_FOR` | `false` (`true` in the prod Compose file) | client IP from `X-Forwarded-For` |

Both binaries (`relay` and `server`) read them, as they read `CALLS_*`.

## PR 9: invoke by name, default agents, `/mcp` additions, waiting (§6.1–6.2, §6.4, §6.6, §7.1)

### One invoke path (`handlers/invoke.rs`)

- `TrustedOutcome` becomes `Outcome`, with a fourth variant `QuotaExhausted { quota, resets_at }`.
- `invoke_public` becomes `authorize_and_enqueue_public(…) -> Result<Outcome, ApiError>`. REST
  maps outcomes to responses exactly as today (the 429 quota payload included).
- `pub(crate) async fn start(state, user, target, input, opts) -> Result<Outcome, ApiError>`:
  - `Target::Grant(id)` and `Target::Public(capability_id)` need `opts.as_agent` (REST's
    `grantee_agent_id`, required as today);
  - `Target::Named { agent: AgentRef, capability: String }` resolves the caller by §6.1
    (`mcp::caller`), then runs the grant or public path.
- REST `POST /v1/invoke` and MCP `invoke` call `start`. MCP's own copy of the outcome mapping
  goes. Nothing new runs on REST's path.

### Caller rules (`mcp/caller.rs`, §6.1)

For `Named`, after the target agent resolves (`discovery::profile::resolve`, so visibility holds)
and its capability is found by name among those the user may see:

1. `as_agent` given: it must be one of your agents in scope (`chk.auth.out_of_scope`
   otherwise). An active, unexpired grant from it for the capability → grant path; else a public
   capability → public path; else `chk.policy.grant_required`.
2. Else the oldest active grant held by one of your agents in scope → grant path, as that agent.
3. Else a public capability → your default agent:
   - unscoped credential: the personal agent;
   - `own` or `selected` with exactly one agent in scope: that agent;
   - `own` with none: a client agent made for this credential;
   - otherwise `chk.mcp.as_required`.
4. Else `chk.policy.grant_required`, saying how to get access (befriend with
   `propose_friendship`, then ask for a grant).

The scope mode comes from `auth::resolve_grant` (one query; named invoke is off REST's path).

### Default agents (migration `0052_default_agents.sql`, §6.4)

- `default_agents (key TEXT PRIMARY KEY, user_id UUID NOT NULL REFERENCES users ON DELETE
  CASCADE, agent_id UUID NOT NULL REFERENCES agents ON DELETE CASCADE, created_at)`; a new, cold
  table.
- `mcp::caller::default_agent(state, user, kind)`: in one transaction,
  `pg_advisory_xact_lock(hashtext(key))`, reuse a live agent, else create one in the user's
  individual account and upsert the row (a deleted default agent is replaced).
  - **Personal** (`user:<id>`): "<user's name> (personal)", slug `personal`, else
    `personal-<4 hex>`.
  - **Client** (`oauth:<client>:<user>` or `api_key:<id>`): "<user's name> via <client or key
    name>", slug `via-<name>` cut to fit, else with `-<4 hex>`; `created_by_client_id` or
    `created_by_api_key_id` set, so it's in the credential's `own` scope; the scope cache entry is
    dropped.
  - Both: private, pull, `accept_calls = nobody`, a description saying what they're for.
- Key rotation (`app/src/handlers/api_keys.rs`) moves the key's row to the new key id.
- The web Agents page labels them (PR 9 adds `default_kind` to the agent DTO: `personal` |
  `client` | null).

### `/mcp` additions (§6.2)

- `search_agents {q?, capability?, tags?, mode?, callable?, include_dormant?, limit?, cursor?}`
  and `featured_agents {}`: listed only with `DISCOVERY_V2`. `get_agent_profile {agent}`: always.
  The featured query moves into `discovery::featured`, shared with REST.
- `get_agent` takes `agent` (id or `acct/slug`) as well as `agent_id`.
- `list_network_agents` rows gain the §5.2 fields (`discovery::fields::load`).
- `invoke` takes one of `grant_id`, `capability_id`, or `agent` + `capability`; with a name,
  `grantee_agent_id` is optional. `wait_seconds` (0–25, default 0): waits, then returns the
  invocation as `poll_invocation` shows it, or its id and status. `awaiting_consent` returns at
  once. A public quota refusal is a tool error, code `monthly_quota_exhausted`.
- `initialize`'s instructions mention finding agents and calling them by name.

### Waiting (`mcp/wait.rs`, §6.6)

`wait_for(state, invocation_id, timeout) -> status`: polls the row's status every 500 ms for 5 s,
then every second, until a terminal status (`succeeded`, `failed`, `rejected`, `timeout`),
`awaiting_consent`, or the deadline. A semaphore (`MCP_MAX_WAITERS`) caps waiters; with none free it
returns at once.

### Tests

- `start`: REST behaviour unchanged (the existing invoke tests), named invoke through a grant, through
  public access with each default-agent rule, `as_required`, `grant_required`, out-of-scope `as`.
- Default agents: made once under concurrent calls; replaced after deletion; an `own` client agent
  is in scope; two users of one client get their own; key rotation keeps the row.
- `/mcp`: the discovery tools (gated), `get_agent` by name, `invoke` by name with `wait_seconds`
  (a stub worker answers), quota refusal, `list_network_agents` fields.
- `wait_for`: returns on success, on `awaiting_consent`, at the deadline, and at once with no
  waiter free.

## PR 10: the shared RPC module, `/mcp/directory` (§6.3, §6.7)

- **`mcp/rpc.rs`:** the JSON-RPC envelope, error codes, `api_err_to_rpc`, the tool-result envelope
  and `initialize`/`ping`, moved out of `handlers/mcp.rs`.
- **`mcp/discovery.rs`:** the discovery tools' schemas and implementations, shared by `/mcp`
  (signed in, with `you`) and the directory (signed out).
- **`POST /mcp/directory`** (`mcp/directory.rs`): no auth extractor and never a 401; 404 unless
  `MCP_AGENTS_ENABLED` and `DISCOVERY_V2`. Tools: `search_agents`, `get_agent_profile`,
  `featured_agents`, `list_reviews {agent}`. Its instructions say to connect `/mcp` or an agent's
  endpoint to call anything.
- **Per-IP limit:** `MCP_DIRECTORY_PER_IP_PER_MIN` through the existing `RateLimiter`, keyed by a
  UUID made from the SHA-256 of the IP. Over: HTTP 429 `directory_rate_limited` with
  `Retry-After`.
- **Client IP** (`mcp::client_ip`): with `TRUST_FORWARDED_FOR`, the last `X-Forwarded-For` entry;
  else the socket peer (`ConnectInfo`, which both binaries now serve with); else unknown (a shared
  bucket).
- **Metering:** not written to `usage_events` (anonymous); a counter
  `chakramcp_mcp_directory_requests_total`. `usage_middleware` skips the path.
- **The prod Compose file** sets `TRUST_FORWARDED_FOR=true`; Caddy already appends the header.
- **Tests:** tools without a token; private agents absent; the limit with and without
  `TRUST_FORWARDED_FOR` (a spoofed header ignored when off); 404 when off; never 401.

## PR 11: agent endpoints (§6.5)

- **`POST /agents/{account_slug}/{agent_slug}/mcp`** (`mcp/agent.rs`):
  - 401 with this endpoint's challenge without a valid token; 404 when the agent is missing,
    deleted, not visible, or the endpoint is off;
  - `initialize`: `serverInfo.name` the display name; instructions from the description plus what
    the tools are, which agent you call as, and `chakramcp_about`; a push agent is a JSON-RPC error
    `chk.mcp.push_agent` with its card URL; `?as=` outside scope is `chk.auth.out_of_scope`;
  - `tools/list`: one tool per capability callable now (granted to an agent of yours in scope, or
    to `?as=`'s agent, plus public ones), names sanitized (`.` → `_`, 64 chars, `_2` on collision),
    `title`, the consent note, the input schema (non-objects wrapped as `{input}`), and the
    `outputSchema` wrapper; plus `chakramcp_about` and `chakramcp_get_result`;
  - `tools/call`: `invoke::start(Named)` as the §6.1 caller, then `wait_for` up to
    `MCP_TOOL_WAIT_SECS`; results per the §6.5 table, `structuredContent` always matching the
    wrapper;
  - usage: one usage event per tool call; `usage_middleware` skips the path.
- **Sign-in discovery:** `GET /.well-known/oauth-protected-resource/agents/{a}/{b}/mcp` serves
  that resource's metadata, and `www_authenticate` names it on the endpoint's 401s.
- **Tests:** each row of the result table with `structuredContent` checked against the wrapper;
  `tools/list` with a grant, public only, and nothing; dotted, long and colliding names; private,
  deleted and push agents; `?as=`; `chakramcp_get_result`'s ownership check; the per-path
  metadata and challenge; the waiter cap.
