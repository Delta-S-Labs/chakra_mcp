# MCP and discovery D2: discovery and addressing — implementation plan

Derived from `2026-10-27-mcp-discovery-design.md` (§ numbers refer to it). D2 is PRs 5–8 of
§13, plus a security fix found while planning (PR 5a). It ships in the release after 0.5.0.
Each PR merges when green.

**Conventions:**
- **Branches:** `fix/d2-private-cards`, `feat/d2-search-profiles`, `feat/d2-tags-cards`,
  `feat/d2-sdks-cli`, `feat/d2-web`.
- **Backend:** relay tests use `#[sqlx::test]` beside the code. After any query change,
  `cargo sqlx prepare --workspace -- --tests` with the local test Postgres on :5544.
- **Frontend:** `pnpm lint` at 0 warnings; `pnpm test` and `pnpm build` pass.

**Names (asked 2026-10-27).** No new uniqueness rule. `account/agent` is already unique: live
account slugs are unique network-wide and never change hands (accounts can't be renamed or
deleted), and agent slugs are unique within their account. Bare agent slugs stay
non-unique; the resolver lists the matches.

## PR 5a: agent cards only for agents the caller may see (found while planning)

`GET /agents/{account}/{agent}/.well-known/agent-card.json` (`handlers/published_cards.rs`)
serves any live agent's card without sign-in, private and org-visible ones included, and its
pull-mode synthesis lists every capability, private ones included. Production has
`DISCOVERY_V2` on, so private agents' names, descriptions and capability names are readable by
anyone who knows or guesses `account/agent`.

**Fix:**
- The agent lookup selects `visibility` and `account_id`. A signed-out caller gets a card only
  for a `network` agent. A signed-in caller also gets the card of an agent in an account they
  belong to, or an `org` agent of an org they share (`auth::shares_org_with_account`). Others:
  404 `agent not found` — the same answer as a missing agent, so the existence of a private
  agent isn't revealed.
- The pull synthesis lists only the capabilities that caller may see: `network` ones for
  everyone, `org` ones for org-sharers, all of them for members.
- A card served to a signed-in caller gets `Cache-Control: private, no-store`; signed-out
  responses keep `public, max-age=300, s-maxage=3600`. Both get `Vary: Authorization`.
- A renamed agent's old slug redirects only for callers who may see it, and a deleted
  agent the caller may not see is 404, not 410.
- An invalid or expired token: 401, as elsewhere.
- Push-mode agents follow the same visibility rule (their upstream card is the owner's to
  publish, so its skills pass through unchanged).

**Tests:** private and org agents 404 signed out and to strangers, and serve to members and
org-sharers; private and org capabilities absent from a network agent's public card; the
cache headers both ways.

## PR 5: search, shared fields, profiles, standing (§5.1–5.5, §7.2)

### Migration `0051_search_vector_v2.sql`

1. `agents_search_vec_compose(slug, display_name, description, account_display_name, tags,
   cap_text)`, `IMMUTABLE`. Each weight gets a `simple` and an `english` vector:
   A = display name and slug; B = account name and tags; C = description and capability text.
2. `agents_refresh_search_vec()` replaced: calls the new compose with capability text from
   `visibility = 'network'` capabilities only.
3. In the 0036 lock loop (100 ms `lock_timeout`, back off, up to 50 tries): `LOCK TABLE agents
   IN ACCESS EXCLUSIVE MODE`, then recreate `agents_search_vec_update` as `BEFORE INSERT OR
   UPDATE OF display_name, description, account_id, tags, updated_at, slug`.
4. `DROP FUNCTION agents_search_vec_compose(TEXT, TEXT, TEXT, TEXT)` (the old signature; only
   0013 uses it).
5. `discovery_query(q TEXT) RETURNS tsquery`, `STABLE`, plpgsql:
   - splits `lower(q)` on `[^[:alnum:]]+`;
   - per word, the `simple` lexeme and the `english_stem` lexemes (`ts_lexize`; stop words
     give none), OR-ed together;
   - prefix (`:*`) for words of three or more characters, whole lexeme otherwise;
   - lexemes are quoted when built, so no input can inject tsquery syntax;
   - `NULL` when no word survives.
6. Re-index: `UPDATE agents a SET search_vec = agents_search_vec_compose(…)` for every row. This
   runs under the lock from step 3. It moves every agent's `updated_at` (the
   `agents_updated_at` trigger), as the spec accepts.

**Measure first:** on the local test database, seed 5,000 agents with 3 capabilities each and
time step 6. Expected: well under a second. Production has a few hundred.

### `relay/src/discovery/` (new module)

- `mod.rs`: `Viewer { user_id, scope: InScope }`, `visible(visibility, is_member, shares_org)`,
  `cache_headers(signed_in, public_value)`, the `MaybeUser` extractor.
- **`MaybeUser`:** no `Authorization` header → `None`; a header that doesn't authenticate →
  401 `ApiError::Unauthorized` (the `www_authenticate` layer adds the challenge).
- `fields.rs`: `AgentSummary` (§5.2's fields without `capabilities`), `CapabilityBrief {id,
  name, access}`, and `summaries(state, viewer, ids) -> Vec<(AgentSummary,
  Vec<CapabilityBrief>)>` in `ids` order. Two queries:
  - agents by `id = ANY($1)`, with live friend count, review aggregates, `online`,
    `last_seen_at` (pull: `COALESCE(h.last_polled_at, a.created_at)`; push:
    `COALESCE(a.agent_card_fetched_at, a.created_at)`), `featured`, effective
    `accept_calls`, and the viewer's `is_member` and `shares_org` per row;
  - capabilities by `agent_id = ANY($1)` ordered by name, filtered in Rust: `network` for
    everyone, `org` for org-sharers, all for members. `access` is `public` when
    `public_invoke` and the agent is `network`-visible, else `friends`.
  - `effective_accept_calls` moves here from `handlers/agents.rs`.
- `search.rs`: the ranked query (below).
- `profile.rs`: `resolve_ref(state, viewer, ref) -> Option<Uuid>` (id, or `acct/slug`, through
  live slug aliases; 404 unless visible to the viewer) and `profile(state, viewer, id)`.
- `standing.rs`: `standing(state, user, target_ids) -> HashMap<Uuid, You>` (below).

### Search (`GET /v1/discovery/agents`)

The handler becomes `ApiResult` (errors in the standard `{error: {code, message}}` shape;
the release notes say so) and takes `MaybeUser`. One query returns the page's ids:

```sql
WITH qry AS (SELECT discovery_query($q) AS tsq)
SELECT a.id, count(*) OVER () AS total
  FROM agents a JOIN accounts acc … LEFT JOIN agent_heartbeats h …
 WHERE <audience> AND <dormancy> AND <filters>
   AND ((SELECT tsq FROM qry) IS NULL OR a.search_vec @@ (SELECT tsq FROM qry))
   AND <keyset cursor, unranked only>
 ORDER BY <exact> DESC, <rank> DESC, <online, ranked only> DESC, a.created_at DESC, a.id DESC
 OFFSET $offset LIMIT $limit + 1
```

- **Audience:** signed out, `visibility = 'network'`. Signed in, also agents of accounts you
  belong to, and `org` agents of orgs you share.
- **Exact:** `lower(btrim(q))` equals the slug, the lowered display name, or `acct/slug`.
- **Rank:** `ts_rank_cd(a.search_vec, tsq)` (default weights), 0 without `q`.
- **Ranked** (a `q` with any alphanumeric character): an offset cursor `{o: n}`; no next page
  past offset 1,000. **Unranked:** the `(created_at, id)` keyset cursor, as now. The cursor
  carries its kind; a mismatched one is 400.
- **Filters:** `capability` is a case-insensitive substring of a visible capability's name
  (`strpos(lower(c.name), lower($c)) > 0`, `network` capabilities for signed-out viewers);
  `tags` all-of; `mode`; `verified`; `capability_schema`; `include_dormant`.
- **`callable=true`:** signed in only (400 otherwise). Agents with a public capability, or an
  active grant to one of your agents in scope (`grantee_agent_id = ANY($in_scope)`).
- **`total_estimate`:** the window count, first page only.
- **Rows:** `summaries()`, then each row is the summary, `capabilities`, the deprecated
  `agent_slug` and `has_public_capabilities`, and `you` when signed in.

### Featured, the network list

- **Featured** keeps its selection query and builds rows with `summaries()`, keeping
  `agent_slug` and `public_capabilities` (the web uses them) for one release. Takes
  `MaybeUser` for the cache headers only.
- **`/v1/network/agents`** keeps its query, audience and order, and flattens `summaries()`
  into each row beside its own fields (`account_id`, `account_display_name`, `endpoint_url`,
  `updated_at`, `is_mine`, `capability_count`). New on it: `capabilities`, `last_seen_at`,
  `friend_count`, `featured`, `visibility`. A test pins the existing fields.

### Profiles and standing

- **Routes:** `GET /v1/discovery/agents/{account_slug}/{agent_slug}`,
  `GET /v1/discovery/agents/{id}`, `GET /v1/discovery/standing?agent=<ref>`.
- **Profile body:** the summary, then:
  - `owner {account_slug, display_name, verified}`;
  - `reviews {avg_rating, count, latest}`: the three newest un-hidden reviews, `by` the
    reviewer's display name when that agent is live and `network`-visible, else "An agent";
  - `capabilities`: the visible ones in full (`description`, `input_schema`,
    `output_schema`, `access`, `public_monthly_quota_per_agent`, `consent_required`,
    `semantics`);
  - `how_to_call`: `cli` (`chakramcp invoke ensure acct/slug <first capability> '{}' --from
    <your-agent> --wait`), and for `network` agents `a2a_card` and `profile`. `mcp` is added
    in D3, when the endpoint exists;
  - `you` when signed in.
- **`You`:** for the credential's agents in scope (from the scope cache), excluding the
  target:
  - `callable`: per visible capability, `via: grant` with the oldest active, unexpired
    grant's grantee, else `via: public` for a public one;
  - `friendships`: `proposed` and `accepted` rows between your agents and the target;
  - `can_start_call_as`: with calls on and the target pull-mode and not `nobody`, your
    pull agents in its account, any for `anyone`, or accepted friends for `friends`
    (`calls/lifecycle.rs`'s rule).
  Three queries per page, batched over the page's targets.
- **Gating:** `DISCOVERY_V2` off → profiles and standing need sign-in (401 signed out);
  search and featured stay 404.
- **Caching:** signed out, `public, max-age=30, s-maxage=120` (profiles) as search; signed in,
  `private, no-store`; `Vary: Authorization` on both.

### Tests (relay)

- 0051 runs; the old compose signature is gone; a slug change updates the vector.
- `discovery_query`: OR semantics, prefix at 3+, whole words under 3, stemming ("booking"
  finds "book a room"), stop words, punctuation-only `q` = no `q`, injection-shaped input.
- Ranking: exact slug > display-name match > tag match > description match; more matched
  words rank higher; online breaks ties only when ranked.
- Private capability text is no longer findable.
- Offset paging (and the 1,000 cap), keyset paging unchanged, mismatched cursor 400.
- Signed-in search shows your private and org agents with `visibility`, `callable`, `you`.
- Profiles: signed out, signed in, by id and by name, through a slug alias, `DISCOVERY_V2`
  off; private and org agents hidden from others and shown to members; reviews' `by`.
- Standing: grant, public, friendship, calls rows; scope narrows it.
- Cache headers with and without a token; 401 on a bad token.
- The network list's existing fields are unchanged.

## PR 6: tags, getting found, A2A cards (§5.6–5.8)

- **Rules in `chakramcp_shared::agent_rules`:**
  - `normalize_tags(Vec<String>) -> Result<Vec<String>, String>`: trim, lowercase, drop
    duplicates, at most 10, each `^[a-z0-9-]{1,32}$`;
  - `check_description(visibility, description)`: `network` needs 20+ characters after
    trimming.
- **Where they apply:**
  - relay `POST /v1/agents` (`tags`, description rule when `network`);
  - relay `PATCH /v1/agents/{id}` (`tags`; the description rule when the result is `network`
    and the visibility or description changes);
  - MCP `create_agent` (its own insert: `tags` and the rule) and `update_agent`'s schema
    (`tags`; it bridges to PATCH);
  - the app's device approval (`app/src/handlers/oauth.rs`, new agents with `network`).
  Errors: 400 `invalid_request` with the rule in the message.
- **Pairing page** (`app/pair/ConsentForm.tsx`): "Who can find this agent?" with *Only my
  account* (private) and *Anyone on the network* (network), both explained, nothing
  preselected unless the device hinted it; org stays available as a third choice when the
  user belongs to an org. With *Anyone on the network*, the description field is required
  and counts to 20.
- **The web create and edit forms** say the same, so the API rule never surprises.
- **A2A cards:** each pull-card skill gets the agent's tags; `documentation_url` is the web
  profile (`{frontend}/agents/{a}/{s}`). A2A's AgentCard has no card-level tags field, so the
  card itself doesn't gain one. Push cards pass through.
- **Tests:** tag rules (count, format, duplicates, case), the description rule on each path,
  rotation-free existing agents untouched, card tags and documentation URL.

    network list on a 404 from an older relay.
- **Docs that name commands** pass the documented-command test.

- The SDKs bump minor versions (TS/Py 0.6.0, Go v0.4.0, Rust 0.4.0); the CLI and server go
  to the next minor.
- Notes:
  - search ranks, matches any word, stems, and no longer finds private capability text;
  - discovery errors use the standard error shape;
  - profiles and standing endpoints; review text is public on profiles;
  - `agent_slug` and `has_public_capabilities` (search) and `public_capabilities`

  - agent cards of private and org agents are no longer public (PR 5a).
