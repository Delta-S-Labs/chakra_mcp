Derived from `2026-10-27-mcp-discovery-design.md` (§ numbers refer to it). D1 is PRs 1–4 of
§13, then the 0.5.0 release. Each PR merges when green.

**Conventions:**
- **Branches:** `fix/d1-deleted-agents`, `fix/d1-scope`, `fix/d1-cli-sdks`, `fix/d1-discovery-web`.

## PR 1: deleted agents (§4.1)

**Revoke on delete.** In `relay/src/handlers/agents.rs` (`delete`, around line 1150), inside
the transaction that sets `tombstoned_at`:
- revoke every active grant where the agent is granter or grantee, with
  `UPDATE grants SET status = 'revoked', revoked_at = now() … RETURNING id`;
- record a `grant.revoke` audit event per returned id, summarised "revoked: agent deleted".

**Migration `0050_revoke_grants_of_deleted_agents.sql`:**
- the same UPDATE for grants whose granter or grantee agent, or that agent's account, has
  `tombstoned_at`;
- the reason goes in no column, so it isn't audited;
- `grants` isn't one of the hot tables, so no lock loop is needed. Check that nothing hot-path
  holds long locks on it.

**Tombstone filters** (`a.tombstoned_at IS NULL AND acc.tombstoned_at IS NULL`, joining
accounts where needed):
- `handlers/invoke.rs`:
  - the trusted path's grant lookup (around 641–680), both agents;
  - the public path's capability lookup (`capability_id`);
  - the inbox agent lookup (around 1357);
- `handlers/friendships.rs`: the agent lookup (around 183);
- `handlers/capabilities.rs`: `list` (around 176–181) returns 404 for a deleted agent, which
  also fixes MCP `list_capabilities`, a bridge to it;
- `handlers/mcp.rs`: `list_network_agents` (around 814) adds the filters. `delete_agent`'s
  description stays true now.

**Tests (relay):**
- deleting a granter or grantee agent revokes both grant directions and writes audit events;
- invoking through a deleted agent's grant, or a deleted agent's public capability, gets 404;
- a deleted agent's inbox gets 404;
- `list_network_agents` and capability lists skip it;
- the migration revokes a pre-existing tombstone's grants (insert a tombstoned agent with an
  active grant, run the statement, check).

## PR 2: scope on every action (§4.2)

**The scope cache** (`relay/src/auth/scope_cache.rs`, or `relay/src/scope_cache.rs` if
`auth.rs` stays a single file):
- `ScopeCache` in `RelayState`: a `DashMap` (or `moka` if it's already in the tree) from
  `CredKey` (`Jwt(jti)` | `ApiKey(id)` | `None` for a session with neither) to `{mode, agents:
  HashSet<Uuid>, fetched_at}`. Entries live 30 s.
- `scope_cache.allows(db, user, agent_id) -> Result<bool>`:
  - **miss:** one query loads the mode and the in-scope agent ids, only in accounts the user
    belongs to (the `own` / `selected` SQL of `manageable_agent_ids`, plus a membership join);
  - **`All`:** true;
  - **otherwise:** set membership, and on `false`, reload once from the database before
    answering.
- `scope_cache.forget(key)`: called where the relay adds a created agent to a credential's set
  (`handlers/agents.rs` around 749, and wherever `own` creation stamps `created_by_*`).
- `auth::require_scope(state, user, agent_id) -> Result<(), ApiError>`: returns
  `ApiError::coded(FORBIDDEN, "chk.auth.out_of_scope", "this credential can't act as that
  agent")`.

**New checks**, after each path's existing membership check:
- `handlers/invoke.rs`: `invoke` for `grantee_agent_id`, on both the trusted path (around 733)
  and the public path (around 1062);
- `consent/reply.rs`: `submit_result` (around 94), for the invocation's target agent. This
  covers REST `/result` and MCP `respond`, if `respond` calls it. Check, and add the check to
  MCP's own path if not;
- `handlers/mcp.rs`: `invoke` (around 1055) if it doesn't go through the REST handler. Plan:
  route it through the handler's core now; PR 9 makes that `invoke::start`;
- `policy/evaluator.rs`: after the caller-agent lookup (around 73–95), for
  `caller_agent_id` with the bearer's credential. `resolve_bearer` must expose the jti or key
  id; refusal gives `chk.auth.out_of_scope` in the A2A envelope.

**Existing scope refusals** move from `ApiError::Forbidden` to `require_scope`. These are the
second `Forbidden` in each membership-then-scope pair:
- `friendships.rs`: 348, 441, 505, 583, 665;
- `invoke.rs`: 1372;
- `consent/notices.rs`: 88;
- `calls/access.rs`: 45;
- `reviews.rs`: 225, 561;
- `grants.rs`: 353, 466;
- `capabilities.rs`: 155;
- `agents.rs`: 874 and the delete check.

Membership refusals stay plain `forbidden`.

**MCP reads**, filtered to in-scope agents as REST's are (#226), using the cached set:
`list_invocations` (851), `poll_invocation` (1140), `list_grants` (957) and
`list_friendships` (1005). A row stays visible when either side is in scope.

**Key rotation** (`app/src/handlers/api_keys.rs`, `rotate`, around 269): in its transaction,
`UPDATE agents SET created_by_api_key_id = $new WHERE created_by_api_key_id = $old`.

**Tests:**
- An `own` token (device flow) and a `selected` key, each against a second agent in the same
  account, get 403 `chk.auth.out_of_scope` on:
  - REST invoke (grant and public);
  - result posting;
  - MCP `invoke` and `respond`;
  - A2A `SendMessage`.
- An unscoped key and a web session still pass.
- MCP's four reads are filtered.
- The existing friendship and inbox tests expect the new code.
- The cache:
  - a hit issues no query (count queries with a test hook, or time it out by closing the pool
    after warming);
  - two tokens of one client get separate entries;
  - a newly created `own` agent works at once;
  - a refusal from a stale set is re-checked;
  - entries expire.
- Rotation keeps an `own` key's agents.

## PR 3: CLI, SDKs and documented commands (§4.3, §4.5, §4.6)

**CLI resolver** (`cli/src/resolve.rs`):
- `mine(api, ident)`: an id, `acct/slug`, or a slug unique among `/v1/agents`;
- `peer(api, ident)`: an id; `acct/slug` by paging `/v1/network/agents` (`{agents,
  next_cursor}`, `limit=100`); a bare slug among your agents first, then unique on the
  network, else an error listing candidates.

Uses:
- `commands/invoke.rs`: replace `resolve_peer` and `resolve_my_agent`;
- `commands/message.rs` (ensure);
- `commands/call.rs`: `my_agent` becomes `mine`, `any_agent` becomes `peer`;
- `commands/reviews.rs`: `resolve_target`;
- `commands/friendships.rs`: `propose --from/--to` resolve names.

Fix the `message_owner` hint in `message.rs` (around 222) to `chakramcp friendships propose
--from <your-agent> --to <peer>`.

**CLI flags and commands:**
- **`configure --token <jwt>`** (and `CHAKRAMCP_TOKEN`):
  - mutually exclusive with `--api-key`;
  - stores `access_token`, with `access_token_expires_at` from the JWT's `exp` (base64 payload,
    unverified);
  - a token without `exp` is stored without expiry.
- **Global `--json`:** `#[arg(long, global = true, hide = true)] json: bool` on `Cli`. It does
  nothing, since output is always JSON.
- **`whoami`** prints the app's `/v1/me`, which gains `credential: {kind, agent_scope, agents}`
  (`app/src/handlers/users.rs` `me`, around 274):
  - `kind` is `api_key` when the caller used one;
  - else `device` if the jti is in `oauth_device_codes.minted_jti`, `oauth` if in
    `oauth_authorizations.minted_jti`, else `session`;
  - the scope comes from `shared::scope::resolve_grant`;
  - `agents` comes from `manageable_agent_ids`, filtered to the user's accounts, or `"all"`.
- **Help text:** reword "your agents" where the command also works on peers. At least
  `capabilities list --agent`, `agents get` and `reviews`.

**SDKs, `network()`:**
- **The fix:** decode `{agents, next_cursor}` and take an optional `cursor`:
  - TypeScript `src/index.ts` (around 143);
  - Python `_sync.py` (around 155) and `_async.py` (around 145);
  - Go `chakramcp.go` (around 110);
  - Rust `client.rs` (around 74).
- **Types:** add a `NetworkPage` type (or the language's equivalent) and test with mocked HTTP.
- **Notes:** each README's changelog note says the return type changed.

**The documented-command test** (`cli/tests/documented_commands.rs`):
- reads `../../.claude/skills/chakramcp-agent/SKILL.md`, `../../frontend/public/llms.txt`
  and every `page.tsx` under `../../frontend/src/app/(site)/docs`;
- collects lines whose first word is `chakramcp`, inside code fences or template literals;
- joins `\` continuations, cuts at `|`, `>`, `&&` and `#`;
- substitutes `$(…)` with `X`;
- splits with `shlex`;
- parses with `Cli::try_parse_from`. `Cli` moves to `cli/src/lib.rs`, or the test uses a
  `pub fn parse_args`;
- skips lines ending `# not-a-command`;
- fails listing every unparsable line with file and line number.

Fix every line it flags in the skill (both copies via the sync script), llms.txt and the
docs.

**Tests:**
- the resolver against a mocked `/v1/network/agents` with two pages;
- `configure --token` with and without `exp`;
- `--json` accepted on `whoami` and `agents list`;
- `/v1/me`'s `credential` for each kind;
- the SDK tests;
- the documented-command test itself.

## PR 4: discovery counts, new agents, install, web, docs (§4.4, §4.7)

**Relay:**
- **Live `friend_count`:** `relay/src/handlers/discovery.rs` (search around 185 and 239,
  featured around 419) replaces `a.friend_count` with `(SELECT count(*) FROM friendships f
  WHERE f.status = 'accepted' AND (f.proposer_agent_id = a.id OR f.target_agent_id = a.id))`.
  Check the friendships columns.
- **The index:** add one on friendships by each agent and status if `\d friendships` shows
  none. Use its own migration with 0036's lock pattern.
- **Dormancy:** in search (around 204), `h.last_polled_at IS NULL OR h.last_polled_at <
  now() - 30 days` becomes `COALESCE(h.last_polled_at, a.created_at) < now() - interval '30
  days'`. Featured gets the same if it filters dormancy.
- **Tests:** a friendship counts; a new pull agent is visible with no heartbeat; one created 31
  days ago with no poll is dormant.

**Install:**
- **npm 11:** run `npm i -g @chakramcp/cli` in a clean container. If the postinstall is
  skipped, move to per-platform packages in `optionalDependencies`, with `bin/chakramcp.js`
  resolving the platform package (the esbuild pattern). Update `packaging/cli/npm` and the
  release workflow that publishes it. Otherwise note `--foreground-scripts` / allow-scripts in
  INSTALL.md.
- **`install.sh`:** if `~/.local/bin` isn't on `PATH`, print the line to add for the user's
  shell.

**Web:**
- `public/.well-known/chakramcp.json`: remove `$schema`.
- `next.config.ts`: a permanent redirect from `/pricing` to `/docs/concepts#limits`.
- `/login` (`SignInPanel.tsx`): the password field's placeholder becomes "Password" (not
  dots); fix the spacing above "Sign in"; the intro mentions email and password.
- `/terms` v0.3, dated the day it merges: "What we collect" adds email-and-password accounts.

**Docs:**
- `/docs/concepts#inbox-invocations`, or the SDK page, says:
  - a pull invocation stays `pending` until claimed, with no relay-side expiry;
  - push forwards time out (with the value from `forwarder.rs`);
  - the SDK `invokeAndWait` timeouts (TypeScript 180 s, and the others' defaults) stop
    waiting, not the invocation.
- `/docs/discover`'s precursor, a paragraph on the discovery docs or CLI page, explains how
  the network list and the directory differ.
